# Руководство для контрибьюторов

Благодарим за интерес к проекту AxOS! Этот документ поможет вам внести свой вклад в разработку.

## Как начать

1. **Сделайте форк репозитория** на GitHub
2. **Создайте ветку** для вашей работы:
   ```bash
   git checkout -b feature/ваше-название
   ```
   или
   ```bash
   git checkout -b fix/ваше-название
   ```
3. **Внесите изменения** и тестируйте их локально
4. **Создайте Pull Request** с описанием изменений

## Стиль кода

### Assembler (NASM)
- Используйте существующие шаблоны в `src/boot/` как пример
- Комментарии на русском языке
- Отступы - 4 пробела
- Имена меток и функций в snake_case

### C (GCC)
- Совместимость с `gcc -m32` в w64devkit
- Используйте флаги `-ffreestanding`, `-fno-builtin` по необходимости
- Комментарии на русском языке
- Стиль отступов - 4 пробела
- Имена функций и переменных в snake_case

## Процесс сборки

### Требования
- Windows
- NASM (`nasm.exe` или `.\tools\nasm.exe`)
- GCC (MinGW/w64devkit)
- Node.js (для упаковки образа)
- QEMU (для тестирования)

### Сборка
```bash
# Сборка загрузчика
.\tools\nasm.exe -f bin src\boot\boot.asm -o build\boot.bin

# Сборка второго этапа загрузчика
.\tools\nasm.exe -f bin src\boot\boot_kernel.asm -o build\boot_kernel.bin

# Сборка ядра
.\tools\nasm.exe -f elf32 src\kernel\kernel_entry.asm -o build\kernel_entry.o
.\tools\nasm.exe -f elf32 src\kernel\idt.asm -o build\idt.o
gcc -m32 -ffreestanding -Isrc\drivers -c src\kernel\kernel.c -o build\kernel.o
ld -m i386pe -T kernel.ld build\kernel_entry.o build\idt.o build\kernel.o -o build\kernel.bin

# Упаковка образа
copy /b build\boot.bin + build\boot_kernel.bin + build\kernel.bin build\os-image.bin
# или через Node.js
node Unknown/packager.js
```

### Тестирование
```bash
# Запуск в QEMU
qemu-system-x86_64 -drive format=raw,file=build\os-image.bin

# С отладкой
qemu-system-x86_64 -drive format=raw,file=build\os-image.bin -d int,cpu_reset
```

## Структура проекта

- `src/boot/` - загрузчик и переход в защищённый режим
- `src/kernel/` - ядро, GDT, IDT, системные вызовы
- `src/lib/` - низкоуровневые утилиты (I/O, память, строки)
- `src/drivers/` - драйверы (клавиатура, экран, GUI)
- `build/` - артефакты сборки
- `docs/` - документация
- `Unknown/` - вспомогательные скрипты и эксперименты

## Правила для Pull Request

1. **Описание**: Чётко опишите, что вы сделали и почему
2. **Сборка**: Убедитесь, что изменения компилируются локально
3. **Тестирование**: Протестируйте в QEMU перед отправкой
4. **Документация**: Обновите README.md или добавьте документацию в `docs/`
5. **Небольшие изменения**: Для небольших правок можно отправлять PR сразу
6. **Большие изменения**: Для крупных изменений сначала откройте issue для обсуждения
