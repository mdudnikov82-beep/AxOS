# Формат образа AxOS

## Обзор

Образ AxOS (`build/os-image.bin`) — это raw-образ дискеты 1.44 МБ
(`1 474 560` байт) без файловой системы на верхнем уровне. Он содержит
загрузчик и ядро, объединённые в один бинарный файл фиксированного размера.
Образ собирается автоматически скриптом `build.bat`.

Отдельно `build.bat` готовит `build/disk.img` (10 МБ, физический диск IDE,
подключается к QEMU как `if=ide`) — в его первых 64 КБ (LBA 0-127) лежит
FAT12-том, который ядро загружает через IDE при старте (`fat12_init()`,
`src/fs/fat12.c`). См. раздел [build/disk.img и FAT12-том](#builddiskimg-и-fat12-том)
ниже.

## Структура образа

```text
┌─────────────────────────────────────────────────────────────┐
│ Байты 0 – 511:        boot.bin (boot.asm)                     │
│ Размер:               512 байт (1 сектор)                     │
│ Описание:             MBR/загрузочный сектор: переключает CPU │
│                       в защищённый режим и грузит kernel.bin  │
├─────────────────────────────────────────────────────────────┤
│ Байты 512 – ...:      kernel.bin                              │
│ Размер:               до 17920 байт (35 секторов)             │
│ Описание:             Ядро AxOS в защищённом режиме           │
│                       (.text/.data/.bss, грузится в 0x1000)   │
├─────────────────────────────────────────────────────────────┤
│ Байты ... – 1474559:  Padding (нули)                          │
│ Описание:             Заполнение нулями до размера дискеты    │
└─────────────────────────────────────────────────────────────┘
```

## Точные смещения

### boot.bin

- **Начало**: байт 0 (сектор 0)
- **Размер**: 512 байт
- **Источник**: `nasm -f bin src/boot/boot.asm -o build/boot.bin`
- **Роль**: загрузочный сектор (сигнатура `0x55AA` в конце), читает
  `kernel.bin` (35 секторов) в `0x1000`, переключается в защищённый режим
  (`switch_to_pm.asm`, `gdt.asm`) и передаёт управление по адресу `0x1000`.

### kernel.bin

- **Начало**: байт 512 (сразу после `boot.bin`)
- **Размер**: переменный, должен не превышать `17920` байт (35 секторов ×
  512), иначе `boot.asm` не загрузит ядро целиком
- **Источник**: линковка объектных файлов ядра (`kernel_entry.o`, `idt.o`,
  `kernel.o`, `screen.o`, `fat12.o`, `paging.o`, `tss.o`, `heap.o`,
  `tasking.o`, `ide.o`, `syscalls.o`, `usermode.o`) через `kernel.ld`
  (`ENTRY(_start)`, секции с адреса `0x1000`) и `objcopy -O binary`
- **Роль**: ядро AxOS — обработка прерываний, paging, TSS/ring3, куча, FAT12,
  IDE, shell

### Финальный padding

- **Начало**: сразу после `kernel.bin`
- **Конец**: байт `1 474 559` (1.44 МБ)
- **Содержимое**: нули — образ дополняется до размера стандартной дискеты,
  чтобы QEMU/реальный контроллер дискет распознал его как floppy

## build/disk.img и FAT12-том

`build/disk.img` — отдельный raw-образ (10 МБ), физический диск IDE
(primary master, подключается к QEMU как `if=ide,index=0,media=disk`).

- **LBA 0-127** (первые 64 КБ): FAT12-том, сгенерированный
  `tools/make_fat12.py` из содержимого `fs/` (`MOTD.TXT`, `STARTUP.CFG`,
  `HELLO.BIN`) в минимальный FAT12-формат (1 FAT, 16 корневых записей,
  1 сектор/кластер) и записанный в `build/disk.img` шагом `build.bat`.
  При старте ядра `fat12_init()` (`src/fs/fat12.c`) читает эти 128 секторов
  через `ide_read_sector` в RAM по адресу `0x20000`; `fat12_write()` после
  успешного изменения зовёт `fat12_flush()`, которая пишет RAM-копию обратно
  через `ide_write_sector` — изменения переживают перезапуск QEMU.
- **LBA ≥128**: свободное место, не используется FAT12-драйвером. Доступно
  через команды shell `diskread <lba>`/`diskwrite <lba> <text>` напрямую
  через `src/drivers/ide.c`.

Если `build/disk.img` отсутствует или первые 64 КБ не похожи на валидный
FAT12-том (`bpb->bytes_per_sector != 512`), `fat12_init()` возвращает 0,
ядро печатает предупреждение, а `ls`/`cat`/`write`/`run` становятся no-op.

## Процесс создания образа

Образ собирается шагами `build.bat` (см. также корневой `README.md`):

```text
1. nasm -f bin src/boot/boot.asm -o build/boot.bin
2. Компиляция и линковка ядра -> build/kernel.bin (через kernel.ld)
3. copy /b build/boot.bin + build/kernel.bin -> build/os-image.bin
4. Дополнение build/os-image.bin нулями до 1 474 560 байт
5. python tools/make_fat12.py -> build/fat12.bin (из содержимого fs/)
6. Запись build/fat12.bin в первые 64 КБ build/disk.img (создаётся/дополняется до 10 МБ)
```

## Ограничения

- **Максимальный размер `kernel.bin`**: 17920 байт (35 секторов) — задаётся
  таблицей чтения диска в `boot.asm`. Если ядро не уместится, его нужно либо
  уменьшить, либо увеличить число читаемых секторов в `boot.asm`.
- **Размер FAT12-тома**: фиксирован — 64 КБ (128 секторов = LBA 0-127 на
  `build/disk.img`), адрес RAM-копии `0x20000` захардкожен в `fat12.c`.
- **Файловая система верхнего уровня**: отсутствует — `os-image.bin` это
  raw-образ дискеты, читаемый только через геометрию CHS, которую понимает
  `boot.asm`.
- **Архитектура**: x86, 32-битный защищённый режим.
- **Порядок компонентов**: жёстко зафиксирован (см. таблицу смещений выше).

## Совместимость

Образ совместим с:

- QEMU (`qemu-system-i386 -drive format=raw,file=build/os-image.bin,if=floppy -boot a`)
- Реальной дискетой 1.44 МБ или образом для USB-эмулятора floppy

## Запуск в QEMU

```bash
# Базовый запуск (как в run.bat)
qemu-system-i386 -drive format=raw,file=build/os-image.bin,if=floppy -boot a

# С логом прерываний для отладки
qemu-system-i386 -drive format=raw,file=build/os-image.bin,if=floppy -boot a -d int
```

## Изменение формата

Если вы хотите изменить формат образа:

1. Обновите `build.bat` (шаги сборки/склейки/паддинга `os-image.bin` и записи
   `fat12.bin` в `build/disk.img`).
2. Если меняется размер FAT12-тома — обновите константы в
   `tools/make_fat12.py`, `FAT12_TOTAL_SECTORS` и адрес `0x20000` в
   `src/fs/fat12.c`.
3. Если меняется лимит размера `kernel.bin` — обновите таблицу чтения секторов
   в `boot.asm`.
4. Обновите эту документацию и карту памяти в `README.md`.
5. Протестируйте сборку (`build.bat`) и загрузку в QEMU (`run.bat`) перед
   использованием на реальном железе.

## История

Ранние версии проекта использовали другой формат — 10 МБ raw-образ
`Unknown/axos_system.img`, собираемый Node.js-скриптом
`Unknown/packager.js` без встроенной файловой системы. Этот формат больше не
используется текущей сборкой (`build.bat`); файлы в `Unknown/` сохранены как
исторический артефакт.

## Будущие улучшения
