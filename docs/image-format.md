# Формат образа AxOS

## Обзор

Образ AxOS (`axos_system.img`) — это raw-диск без файловой системы, предназначенный для загрузки в x86-совместимых системах. Образ содержит загрузчик и ядро, объединённые в один бинарный файл фиксированного размера.

## Структура образа

```text
┌─────────────────────────────────────────────────────────────┐
│ Сектор 0:         MBR / Boot Sector (boot.bin)             │
│ Размер:           512 байт                                  │
│ Описание:         Первый этап загрузчика, загружает второй  │
│                   этап и передаёт управление                │
├─────────────────────────────────────────────────────────────┤
│ Сектор 1-N:       Boot Kernel (boot_kernel.bin)            │
│ Размер:           Переменный (обычно несколько секторов)    │
│ Описание:         Второй этап загрузчика, переключает в PM  │
│                   и загружает ядро                          │
├─────────────────────────────────────────────────────────────┤
│ Сектор N+1-M:     Kernel (kernel.bin)                      │
│ Размер:           Переменный (зависит от размера ядра)      │
│ Описание:         Основное ядро ОС в защищённом режиме      │
├─────────────────────────────────────────────────────────────┤
│ Сектор M+1-20479: Padding (нули)                            │
│ Размер:           До 10 МБ всего                           │
│ Описание:         Заполнение нулями до фиксированного размера│
└─────────────────────────────────────────────────────────────┘
```

## Точные смещения

### boot.bin

- **Начало**: Сектор 0 (байт 0)
- **Размер**: 512 байт (1 сектор)
- **Роль**: MBR, содержит код загрузки и сигнатуру 0x55AA в конце

### boot_kernel.bin

- **Начало**: Сектор 1 (байт 512)
- **Размер**: Переменный, определяется при сборке
- **Роль**: Второй этап загрузчика, переключение в защищённый режим

### kernel.bin

- **Начало**: Сразу после boot_kernel.bin
- **Смещение**: 512 + sizeof(boot_kernel.bin) байт
- **Размер**: Переменный, определяется при сборке
- **Роль**: Основное ядро ОС

### Padding

- **Начало**: Сразу после kernel.bin
- **Конец**: Байт 10,485,760 (10 МБ)
- **Содержимое**: Все нули (0x00)

## Процесс создания образа

Образ создаётся скриптом `Unknown/packager.js`:

```javascript
1. Чтение boot.bin (512 байт)
2. Чтение boot_kernel.bin (переменный размер)
3. Чтение kernel.bin (переменный размер)
4. Конкатенация: boot.bin + boot_kernel.bin + kernel.bin
5. Дополнение нулями до 10,485,760 байт (10 МБ)
6. Запись в axos_system.img
```

## Загрузка

### Этап 1: BIOS → boot.bin

1. BIOS загружает первый сектор (boot.bin) в память по адресу 0x7C00
2. Проверяет сигнатуру 0x55AA в конце сектора
3. Передаёт управление boot.bin

### Этап 2: boot.bin → boot_kernel.bin

1. boot.bin загружает boot_kernel.bin с диска
2. Передаёт управление второму этапу

### Этап 3: boot_kernel.bin → kernel.bin

1. boot_kernel.bin переключает процессор в защищённый режим
2. Настраивает GDT и сегменты
3. Загружает kernel.bin в память
4. Передаёт управление ядру

## Ограничения

- **Максимальный размер ядра**: ~10 МБ (минус размер загрузчиков)
- **Файловая система**: Отсутствует (raw-диск)
- **Архитектура**: Только x86 (32-битный защищённый режим)
- **Порядок компонентов**: Жёстко зафиксирован

## Совместимость

Образ совместим с:

- QEMU (`qemu-system-x86_64` или `qemu-system-i386`)
- Bochs
- VirtualBox (как raw-диск)
- Реальное железо (запись на флешку/диск)

## Запуск в QEMU

```bash
# Базовый запуск
qemu-system-x86_64 -drive format=raw,file=Unknown/axos_system.img

# С отладкой
qemu-system-x86_64 -drive format=raw,file=Unknown/axos_system.img -d int,cpu_reset

# С последовательным портом для отладки
qemu-system-x86_64 -drive format=raw,file=Unknown/axos_system.img -serial stdio
```

## Изменение формата

Если вы хотите изменить формат образа:

1. Обновите `Unknown/packager.js`
2. Измените загрузчики для работы с новыми смещениями
3. Обновите эту документацию
4. Протестируйте в QEMU перед использованием на реальном железе
