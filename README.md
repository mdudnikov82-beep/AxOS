# AxOS

AxOS — экспериментальная операционная система / учебный проект.
Цель проекта — исследовать загрузчик, переход в защищённый режим, простейшие драйверы и собственное ядро.

## Технологии

- Языки: Assembler (NASM), C (GCC)
- Среда: Windows (`w64devkit` / MinGW)
- Инструменты: Node.js (автоматизация сборки), QEMU (эмуляция)
- Архитектура: x86 (32-битный защищённый режим)

## Структура репозитория

- `src/boot/` — код загрузчика, переключение в PM, чтение ядра с носителя.
- `src/kernel/` — ядро, GDT, системные вызовы, базовый UI.
- `src/lib/` — низкоуровневые утилиты: ввод/вывод, память, математика, строки.
- `src/drivers/` — драйверы для GUI, клавиатуры, экрана и UI.
- `build/` — артефакты сборки: образы, бинарники, промежуточные файлы.
- `Unknown/` — вспомогательные скрипты, генераторы и экспериментальные утилиты.
- `w64devkit/` — локальная среда MinGW/DevKit для сборки.
- `Ненужное/` — старые наработки и ветки экспериментов.

## Файлы и роли

### `src/boot/`
- `boot.asm` — основной загрузчик, который загружает следующий этап и передаёт управление.
- `boot_kernel.asm` — второй этап загрузчика, ответственный за загрузку ядра.
- `disk_load.asm` — код низкоуровневого чтения с носителя.
- `switch_to_pm.asm` — переключение процессора в защищённый режим.

### `src/kernel/`
- `kernel_start.asm` — точка входа ядра и базовая инициализация.
- `gdt.asm` — таблица сегментов (GDT) для перехода в PM.
- `syscalls.asm` — реализация системных вызовов.
- `ui_colors.asm` — настройки цветов и интерфейсные константы.
- `kernel.c` — основная логика ядра на C, работа с выводом, управлением и сервисами.

### `src/lib/`
- `io.asm` — низкоуровневый ввод/вывод.
- `mem.asm` — простая работа с памятью.
- `math.asm` — математические операции и вспомогательные функции.
- `print.asm` — вывод строк и символов.
- `string.asm` — работа со строками.

### `Unknown/`
- `packager.js` — собирает финальный raw-образ `axos_system.img`.
- `kernel.js`, `macro_controller.js`, `math_engine.js`, `security_buffer.js` — вспомогательные эксперименты и утилиты.
- `sys_profile.json` — профиль/настройки для экспериментов.

## Формат образа

Подробная документация по формату образа доступна в [`docs/image-format.md`](docs/image-format.md).

Кратко:
- Итоговый образ `Unknown/axos_system.img` создаётся простым объединением двух бинарников:
  1. `Unknown/boot.bin`
  2. `Unknown/kernel.bin`
- После объединения файл дополняется нулями до размера 10 МБ (10 * 1024 * 1024 байт).
- Образ не содержит файловой системы, это raw-диск без FAT/NTFS.
- Загрузчик читает ядро напрямую по фиксированным смещениям, поэтому порядок и расположение бинарников важны.

### Как работает `Unknown/packager.js`

1. Читает `boot.bin` и `kernel.bin` из `Unknown/`.
2. Склеивает их в один буфер.
3. Дополняет буфер нулями до 10 МБ.
4. Пишет результат в `Unknown/axos_system.img`.

> Важно: если вы собираете `boot.bin` и `kernel.bin` в папке `build/`, скопируйте их в `Unknown/` перед запуском `node Unknown/packager.js`.

## Требования

- Windows
- `nasm` / `nasm.exe`
- Node.js (для сборки образа через `Unknown/packager.js`)
- Эмулятор, например `qemu-system-x86_64`
- Опционально: MinGW / `w64devkit`

## Как собрать

1. Соберите загрузчик и ядро:
   - `nasm -f bin src/boot/boot.asm -o build/boot.bin`
   - `nasm -f bin src/boot/boot_kernel.asm -o build/boot_kernel.bin`
   - соберите бинарник ядра из `src/kernel/` (ASM/C в зависимости от текущей реализации).
2. Упакуйте образ:
   - `node Unknown/packager.js`
3. В результате должен появиться образ `Unknown/axos_system.img` примерно 10 МБ.

> Примечание: в текущей ветке `build.bat` отсутствует, поэтому сборку нужно выполнять вручную или через собственный скрипт.

## Как запустить

- `qemu-system-x86_64 -drive format=raw,file=Unknown/axos_system.img`
- Или используйте другой эмулятор/виртуальную машину с поддержкой x86.

### Стиль и требования

- Assembler: NASM-style (используйте существующие шаблоны в `src/boot`).
- C: совместимость с `gcc -m32` в `w64devkit` (используйте флаги `-ffreestanding`, `-fno-builtin` по необходимости).

### Сборка и тест локально

Пример команд (адаптируйте под ваш путь и среду):

```bash
nasm -f bin src/boot/boot.asm -o build/boot.bin
nasm -f bin src/boot/boot_kernel.asm -o build/boot_kernel.bin
# собрать kernel (пример C + линковка)
gcc -m32 -ffreestanding -c src/kernel/kernel.c -o build/kernel.o
nasm -f elf32 src/kernel/kernel_start.asm -o build/kernel_start.o
ld -T linker.ld -m elf_i386 -o build/kernel.elf build/kernel_start.o build/kernel.o
objcopy -O binary build/kernel.elf build/kernel.bin
node Unknown/packager.js
```

### Запуск образа для проверки

```bash
qemu-system-i386 -drive format=raw,file=Unknown/axos_system.img
```

## Troubleshooting

### Ошибка "NASM не найден"
- Установите NASM или добавьте его в PATH
- Или используйте локальную копию в `tools/nasm.exe`

### Ошибка "GCC не найден"
- Установите MinGW или w64devkit
- Добавьте bin-директорию в PATH

### Образ не создаётся
- Проверьте, что Node.js установлен
- Убедитесь, что `boot.bin` и `kernel.bin` существуют в `Unknown/`
- Запустите `node Unknown/packager.js` вручную для диагностики

### QEMU не запускается
- Установите QEMU для Windows
- Используйте полный путь к qemu-system-x86_64.exe
- Попробуйте qemu-system-i386 для 32-битной эмуляции
